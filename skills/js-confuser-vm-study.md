# js-confuser-vm encoder/decoder study

This parent-level note applies the general [encoder/decoder method](encoder-decoder-method.md)
to the pinned JS-Confuser-VM encoder and its target-local `decode-js` reversal. Encoder
mechanisms live in [the encoder package](js-confuser-vm/js-confuser-vm.md); decoder
mechanisms and acceptance live in [the decoder package](decode-js/decode-js.md).

## Scope

The plugin's goal is recovery of any valid file produced by the pinned JS-Confuser-VM
release, regardless of source program, encoder option vector, or randomized emission.
The currently qualified baseline is tag `0.1.5` with optional hardening disabled;
it is an implementation boundary, not the goal's boundary. Earlier releases, hardening,
repeated or mixed encoders, and cross-encoder generalization have no qualification from
that baseline. Other releases need separate shape and behavior qualification. Runtime
correctness is a bounded regression guard, not evidence that VM structure was recovered.

Build coverage from the encoder outward: inventory compiler/runtime shapes and option
interactions, generate source-feature cases across options and seeds, record provenance,
and compare encoded behavior with executable step-one and recovered step-two output.
Check structural coverage, complete semantic recovery, residue, and atomic decline as
separate axes. Fresh generated cases challenge the implementation beyond committed
fixtures. Finite generated samples do not prove the universal goal by themselves.
An independent VM-2 decoder benchmark remains a separate acceptance step. Generate and
retain its source, encoded input, expected behavior and provenance alongside its test.
Report recovery quality and measured runtime separately; that sample must not define
the plugin's recognition rules or replace generated encoder coverage.

## Method dispositions

| Rule | Durable application or boundary |
|---|---|
| T8, T6 | Challenge source-derived mechanisms with focused generated behavior and the actual static decoder; instrument the failing layer before assigning cause. Source reading alone is not decoder proof. |
| T7 | Check compiler definitions against runtime handlers in both directions, consume each word exactly, and assert complete recovery and residue inventories. Add equivalent checks for each new representation. |
| T1 / W4, W1 | Follow compiler finalization and serialization dependencies: symbolic register, label and constant forms become numeric words and constant pairs. Decoder dependency order belongs to the target-local recovery contract; opcode number, source order and output size do not order work. |
| V1 | One frozen release supports no earlier-release or era claim. Open a version axis only when studying another release. |
| W6 | Repeated or mixed-encoder virtualization is unexercised and outside this boundary. |
| W7, T4 / W3 | A target-local adapter preserves other callers' contracts. Any shared change requires a consumer and workaround inventory, off-target negatives and a cluster-level design decision. |
| T9, T3 / W2 | A predecessor must provide complete immutable records. Missing roles, malformed words, invalid references or routes, and unsupported instructions decline atomically. Diagnose a new residue at its producer, schedule, information route and consumer before widening a matcher. |
| T2 / W5, S6 | Structural identity, complete predecessor reconstruction, coverage and atomic preflight precede fresh emission. Compare live derived state with a fresh parse wherever a pass mutates a tree. Partial function, CFG, closure, handler or interpreter state is not published. |
| S1–S3 | Size is secondary. Census instruction, operand, target, function, CFG, closure, exception, semantic and VM residue axes; supported output has no VM runtime or wordcode residue. Helper removal needs the complete static proof. |
| S4, S5 | Keep behavior oracles bounded and freeze generated bytes before comparisons. Ratios, counts and hashes belong to the evidence for that run. |
| T5 | Use an isolation matrix only for a combination gap with no place for a T6 breadcrumb. Optional hardening combinations are outside the supported baseline. |

## Evidence and updates

The pinned encoder's [container](js-confuser-vm/container-wordcode.md) and
[instruction set](js-confuser-vm/instruction-set.md) define emitted shapes. The
[decoder visitor map](decode-js/plugins/jsconfuser-vm.md#visitor-dependency-map),
target-local pages and the
[sequential coordinator](decode-js/plugins/jsconfuser-vm-sequential.md) define recovery
and caller boundaries. Their fixtures and tests hold accepted claims; ignored generated
evidence is not a package dependency.

Update a disposition only when qualifying evidence changes its mechanism or scope.
Keep `unexercised`, `not applicable` and `outside scope` distinct. A general
method change belongs in the general method and its keyed incident.
